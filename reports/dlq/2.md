## Root cause

MongoDB orders collection enforces `$jsonSchema` requiring every `lineItems[]` element to include a `product` object (`seeds/mongo-init.js`).

Order **100** has 10 line items referencing Postgres products **31–40**. In production those products still had `migrated_at IS NULL` (product migration had not stamped them yet), while other products in the slice were already migrated.

`BackfillService.toOrderDocument` built the embed map with:

```java
productJpaRepository.findById(lineItem.getProductId())
    .filter(product -> product.getMigratedAt() != null)
    .ifPresent(...)
```

Products 31–40 were excluded, so `OrderTransformer.toEmbeddedLineItems` emitted line items with no `product` field. Mongo rejected the bulk upsert at **lineItems index 9** (the 10th item, product id 40).

## Reproduction

1. Isolated stack: `docker compose -p dlq-2 -f docker-compose.dlq.yml up -d`
2. Seed: `./scripts/dlq-seed-subset.sh orders 91 100 localhost 15432`
3. Confirmed data:
   - `SELECT product_id, migrated_at IS NULL FROM products WHERE product_id BETWEEN 31 AND 40` → all unmigrated
   - Order 100 has 10 line items for products 31–40
4. Before fix, backfill would record the same schema validation failure for batch pk 91–100.

## Fix

Remove the `migratedAt != null` filter in `BackfillService.toOrderDocument`. Always load referenced products from Postgres and embed them in order documents. Postgres is the source of truth during backfill; Mongo product migration status must not determine whether a denormalized embed is present.
