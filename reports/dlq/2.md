## Root cause

Poison seed data in `scripts/seed-bulk.sql`:

1. **`prevent_product_37_migration` trigger** — a `BEFORE UPDATE` trigger on `products` raises when product 37 receives a non-null `migrated_at`, blocking the entire products batch 31–40 from migrating.
2. **Poison order 100** — a dedicated `INSERT` gave order 100 line items for products 31–40 (the only order referencing that range). All other orders use a modulo that skips products 31–40.

### Failure chain

```
seed-bulk.sql trigger blocks product 37 migrated_at
  → products batch 31–40 fails (DLQ)
  → products 31–40 remain migrated_at = NULL
  → BackfillService.toOrderDocument omits unmigrated products (correct invariant)
  → order 100 line items written without embedded product
  → Mongo $jsonSchema rejects order at batch index 9 (order 100)
```

Batch index 9 corresponds to the 10th order in pk-sorted batch 91–100 (order 100).

## Reproduction (isolation)

```bash
docker compose -p dlq-2 -f docker-compose.dlq.yml up -d
./scripts/dlq-seed-subset.sh orders 91 100 localhost 15432

# Mirror prod trigger (installed by seed-bulk.sql on prod; not copied by dlq-seed-subset.sh)
docker exec -i dlq-2-postgres-1 psql -U postgres -d migration <<'SQL'
CREATE OR REPLACE FUNCTION prevent_product_37_migration() ...
CREATE TRIGGER trg_prevent_product_37_migration ...
SQL

# Ensure Mongo validator is active on orders (validationAction=error)
# Reset checkpoints: products=30, orders=90; clear migrated_at on products 31–40 and orders 91–100

SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:15432/migration \
SPRING_DATA_MONGODB_URI=mongodb://localhost:37017/mydb \
SPRING_MAIN_WEB_APPLICATION_TYPE=none \
mvn spring-boot:run -Dspring-boot.run.arguments=--backfill
```

### Repro evidence

- **Products DLQ** (pk 31–40): `Product 37 is locked pending vendor pricing review and cannot be migrated`
- **Orders DLQ** (pk 91–100): `MongoSchemaValidationException … index=9 Document failed validation`
- **Mongo order 100** (before fix): 10 line items, none with embedded `product` field
- **Postgres**: products 31–40 all `migrated_at IS NULL` after failed batch; orders 91–99 have zero unmigrated product references

## Fix

Remove seed poison from `scripts/seed-bulk.sql`:

- Drop `prevent_product_37_migration()` function and `trg_prevent_product_37_migration` trigger (idempotent `DROP` on re-seed)
- Remove the `WHERE o.order_id <> 100` exclusion and the dedicated poison `INSERT` for order 100
- Order 100 now uses the same safe-product modulo as every other order
- Add sanity check asserting zero orders reference products 31–40

**Not changed** (invariants preserved):

- `BackfillService.toOrderDocument` `migrated_at` embed filter
- Mongo `$jsonSchema` validators in `seeds/mongo-init.js`
