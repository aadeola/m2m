# DLQ triage report — entry 1

## Entry

| Field | Value |
|-------|-------|
| id | 1 |
| entity | orders |
| PK range | 1–1 |
| exception | `com.migration.exception.MongoSchemaValidationException` |
| message | test schema failure for dlq agent |

## Root cause

The `orders` collection validator (`seeds/mongo-init.js`) requires every element of
`lineItems` to include a `product` object (`validationAction: error`, Mongo code 121).

On the `dlqAgent` branch, `BackfillService.toOrderDocument` was changed to only
populate `productsById` for products with `migrated_at IS NOT NULL`. When a
referenced product had not yet been marked migrated (e.g. product migration
halted after a prior batch failure, or a subset re-run where product rows still
had null `migrated_at`), `OrderTransformer.toEmbeddedLineItems` silently omitted
the `product` field. Mongo rejected the bulk upsert with a document validation
error.

## Reproduction

1. Isolated stack: `docker compose -p dlq-1 -f docker-compose.dlq.yml up -d`
2. Seed slice: `./scripts/dlq-seed-subset.sh orders 1 1 localhost 15432`
3. Simulate incomplete product migration:

   ```sql
   UPDATE orders SET migrated_at = NULL WHERE order_id = 1;
   UPDATE products SET migrated_at = NULL;
   UPDATE products SET migrated_at = NOW() WHERE product_id IN (1, 4);
   -- product 6 remains unmigrated; order 1 line item 3 references product 6
   ```

4. With the buggy code, `--backfill` produced a `MongoSchemaValidationException`
   (line item missing required `product`).

## Fix

1. **`BackfillService.toOrderDocument`** — restore unconditional product lookup
   from Postgres (same as `main`):

   ```java
   productsById.computeIfAbsent(lineItem.getProductId(), productId ->
       productJpaRepository.findById(productId)
           .orElseThrow(() -> new IllegalStateException(...)));
   ```

   Backfill already runs `migrateProducts()` before `migrateOrders()`; embedding
   from Postgres does not violate ordering and satisfies the Mongo schema.

2. **`OrderTransformer.toEmbeddedLineItems`** — fail fast with
   `IllegalStateException` when a line item's product is missing from
   `productsById`, instead of writing a schema-invalid document.

## Test evidence

- `mvn test -Dtest=OrderTransformerTest` — passes (embed + fail-fast cases)
- Isolated backfill after fix:

  ```bash
  SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:15432/migration \
  SPRING_DATA_MONGODB_URI=mongodb://localhost:37017/mydb \
  mvn -q spring-boot:run -Dspring-boot.run.arguments=--backfill
  ```

  Result: order `1` migrated, `backfill_dlq` empty, Mongo `orders` document has
  `product` on all three `lineItems`.
